Linux containers on Android.

Droidspaces boots a full Linux distribution on the phone's own kernel, with systemd or OpenRC as PID 1. No emulation and no virtual machine. The runtime is one static binary of about 400 KB.

Current release v6.6.0, GPLv3, source on GitHub.

It runs the whole distribution, not a shell.

Each container gets its own PID, mount, UTS, IPC and cgroup namespace on the phone's kernel. Inside, systemd or OpenRC runs as PID 1 and starts services the way it does on a server.

systemd boots in 150 to 750 milliseconds. Two userspace daemons keep a container alive while the phone is in use, so Android does not throttle or kill its services. Networking is host, NAT over a veth pair, or none.

The runtime is a single static binary of about 400 KB, built against musl, with no dependencies, on any Linux kernel from 3.10. It also runs on ordinary Linux machines.

The app is the control surface.

A Material 3 app installs, starts, stops and edits every container, opens a terminal inside it, and shows CPU, memory, disk and addresses while it runs.

The home screen reports the backend state, the kernel and the architecture. The panel lists uptime and usage per container. Each container has a terminal with tabs and a service manager for its init system.

Leave it running as a home server.

Containers start at boot from init.rc and stay up for weeks. Forward ports, pin a static address on the NAT subnet, choose the upstream interface, and hand the container the phone's hardware one switch at a time.

GPU access uses Turnip on Adreno. USB, block devices, sensors and serial ports pass through with hardware access. Termux:X11, VirGL and PulseAudio are each one toggle. Docker, Podman and bwrap run inside a container once sandboxing is allowed.

What you need.

Droidspaces runs on rooted Android devices and on ordinary Linux systems.

Android

  • Kernel 3.10 or newer
  • Root through KernelSU, Magisk or APatch
  • A kernel built with the documented configuration
  • aarch64, armhf, x86_64 or x86

Linux

  • Kernel 3.10 or newer
  • Root, or a running droidspaces daemon
  • No custom kernel
  • aarch64, armhf, x86_64, x86 or riscv64
