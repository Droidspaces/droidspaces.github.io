A homelab that keeps running when the power cuts.

Your old Android phone has a battery, mobile data and a Linux kernel. Droidspaces runs Linux containers on Android: a full distribution boots on that kernel, with systemd or OpenRC as PID 1. No emulation, no virtual machine.

Set it up once. Forget it.

Droidspaces is an alternative to Docker and LXC, built for a phone. Your services run the way they would on a Linux server, and after the first setup nothing needs you.

  1. Your phone boots.

    After an update, a reboot or a flat battery.

  2. Droidspaces starts your containers.

    From init.rc or a boot script, before you unlock the phone, while /data is still encrypted.

  3. The init system starts your services.

    systemd or OpenRC brings up every enabled unit. No app to open, no command to type.

A real Linux, not an emulation.

Each container gets its own PID, mount, UTS, IPC, cgroup and network namespace on the phone's kernel, behind NAT by default. systemd boots as PID 1 in 150 to 750 ms.

  • systemd
  • OpenRC
  • runit
  • s6
  • PID namespace
  • Mount namespace
  • Cgroup v1 and v2
  • journald

It sits on your network like a server.

Each container has its own monitor process, detached from the app, so closing or uninstalling the app stops nothing. Inside, it runs services the way a Docker or LXC host does. Docker on Android runs nested in a container too, on every supported kernel.

  • Host networking

Run it from the app.

Install, start, stop and edit containers, open a terminal inside one, and watch its CPU, memory and addresses. The phone's hardware is one switch each.

Get it running.

The APK carries the runtime and the app, and the docs list the phones known to run it. Linux gets a static tarball.

Android

  • Kernel 3.10 or newer
  • Root through KernelSU, Magisk or APatch
  • A kernel built with the documented configuration
  • aarch64, armhf, x86_64 or x86

Linux

  • Kernel 3.10 or newer
  • Root, or a running droidspaces daemon
  • No custom kernel
  • aarch64, armhf, x86_64, x86 or riscv64
